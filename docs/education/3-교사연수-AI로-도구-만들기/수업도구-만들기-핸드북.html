00시작하기 전에

프로그래밍 지식은 필요 없습니다. 대신 "이건 아니다"라고 말할 수 있어야 합니다 — 수업을 설계할 때 쓰는 그 능력입니다.

필요한 것 이걸 어디에 쓸지 안다

MakerLab에 넣을 SVG, 교실 PC에서 설치 없이 — 쓰임새와 환경이 분명하면 나머지는 Claude가 채웁니다.

필요 없는 것 프로그래밍 지식

언어·도구·수학 모두 몰라도 됩니다. 영어로 길게 쓸 필요도 없습니다. 실제로 쓴 요청 중에는 "다시 확인" 같은 두 글자짜리도 있습니다.

01시작하기 — 첫 한 마디가 2주를 결정합니다

처음에 정한 쓰임새와 제약이 59번 고치는 동안 한 번도 흔들리지 않았습니다.

기능으로 말하면 이미지를 벡터로 변환하는 프로그램 만들어 줘

그럴듯한 게 나오지만, 내 장비에서 안 열리는 파일일 수 있습니다.

쓰임새로 말하면 MakerLab에 넣을 SVG, RDWorks에서 열릴 DXF

그 장비가 요구하는 조건까지 맞춰 줍니다. 실제로 RDWorks가 2차 곡선을 못 읽는 문제를 알아서 찾아 고쳤습니다 — 제가 몰랐던 문제입니다.

교사가 꼭 말해야 할 제약

학교 환경은 제약이 많습니다. 제약은 족쇄가 아니라 설계 조건이라, 먼저 말할수록 결과가 좋아집니다. 늦게 말하면 다 만든 뒤에 갈아엎게 됩니다.

제약이렇게 말합니다
설치 여부설치 없이 HTML 파일 하나로 / 설치형으로
인터넷인터넷 안 되는 교실에서도 돌아가야 한다
사용자초등 5학년 25명이 각자 PC에서 쓴다
개인정보학생 이름을 서버로 보내지 않는다
장비우리 학교 레이저는 RDWorks를 쓴다
결과: 2주 내내 서버도 회원가입도 끼어들지 않았고, 학생 배포는 USB로 파일 하나 복사하는 것으로 끝났습니다.

02키우기 — 한 번에 기능 하나씩

10월 12일 하루에 커밋 27개. 각각은 5~20분짜리 작은 요청입니다. 쉬는 시간에 하나, 퇴근 후에 두세 개.

"다 만들어 줘"라고 하면 어디가 틀렸는지 찾을 수 없습니다. 하나씩 하면 매번 확인하고 넘어가고, 잘못돼도 그 하나만 되돌리면 됩니다.

실제로 보낸 요청은 이 정도 길이입니다

치수의 폰트 크기를 줄이기! 숫자를 선에 가깝게 해야함.. 지금은 이미지랑 너무 근접하고 선과는 너무 멈
지우는게 어딧지?
안되겠다 이거 다른 배포 계정으로 옮기자
주소를 유지하고 싶어서 그래
다시 확인
만듦
부담 내려놓기: 맞춤법이 틀려도, 반말이어도, 두 글자여도 됩니다. 앞 대화가 이어지고 있으니까요. 멋진 프롬프트를 쓰려고 시간을 들이지 마세요.

03고치기 — 원인 말고 증상으로

가장 자주 하게 되는 단계이고, 말하는 방식이 결과를 가장 크게 바꿉니다.

원인을 추측해서 말하면 그쪽만 보게 됩니다. 보이는 대로만 말하면 전체를 살펴보고 진짜 원인을 찾습니다.

상황아쉬운 신고좋은 신고
화면이 이상CSS가 깨진 것 같아요오른쪽 글자가 화면 밖으로 나가요
결과가 틀림계산 로직 고쳐 줘10mm로 넣었는데 12mm로 나와요
반응이 없음이벤트가 안 걸렸나 봐요버튼을 눌러도 아무 일이 없어요
오류 창오류 났어요오류 문구를 그대로 복사해서 붙여넣기

이 프로젝트에서 실제로 쓴 신고

내가 쓴 말실제 원인과 수정
키캡이 자꾸 오른쪽 위로 밀림위치 계산 기준이 그림이어서 — 고정 좌표로 변경
텍스트 모드에서 폭의 상태가 실제와는 다름계산식 추정 방식 → 실제로 그려서 재는 방식으로 교체
가운데 섬은 왜 안됐지구멍과 도형이 겹칠 때 고르는 우선순위 문제
"왜 안됐지" 한마디로 충분합니다. 화면 캡처를 붙여 넣으면 더 빠릅니다. 오류 문구는 번역하거나 요약하지 말고 그대로 복사하세요.

04확인하기 — 눈으로 보여 달라고 하기

"됐습니다"를 믿고 넘어가면 나중에 한꺼번에 터집니다.

이렇게 요구합니다왜
화면을 캡처해서 보여 줘말이 아니라 결과 이미지로 확인
10mm로 넣으면 실제 몇 mm인지 재 봐숫자로 확인하면 어긋남이 바로 드러남
이 기능이 망가지면 알 수 있게 검사를 만들어 줘다음에 고칠 때 자동으로 잡힘
전체적으로 점검해 줘기능을 많이 추가한 뒤에는 꼭
이 프로젝트에는 자동 검사 67개가 쌓였습니다. 전부 "확인해 달라"고 말해서 생긴 것입니다. 기능을 추가할 때마다 다른 데가 망가졌는지 자동으로 잡아 줍니다.

05버리기 — 틀린 방향은 미련 없이

손으로 만들었으면 아까워서 못 버립니다. 다시 만드는 데 10분이면 되니까 과감해질 수 있습니다 — 이게 진짜 장점입니다.

버린 것무엇이 문제였나어떻게 했나
3D 단계 자동 보정가는 선을 출력 직전에 자동으로 굵게 했더니 그림이 통째로 뭉개짐전부 삭제 → 2D 화면에서 사람이 보고 고르는 방식으로
16/32/64/128색 색판색을 많이 고를 수 있게 했더니 학생들이 오히려 헤맴5×5 고정 타일 + "그림에 쓰인 색" 줄로 교체
이미 만든 게 아까워서 붙들고 있으면 도구가 나빠집니다. 만드는 비용이 싸니까, 버리는 비용도 쌉니다.

06복사해서 바로 쓰는 프롬프트 틀

네 가지면 처음부터 끝까지 갑니다. 대괄호 안을 내 상황으로 바꿔서 그대로 붙여넣으세요.

틀 ① 시작할 때

복사해서 쓰기 
[무엇을] 만들고 싶다.

· 쓰는 사람: [초등 5학년 학생 25명 / 나 혼자]
· 쓰는 상황: [교실 PC, 인터넷이 불안정함]
· 넣는 곳: [MakerLab / 한글 / 엑셀]
· 꼭 지킬 것: [설치 없이 HTML 파일 하나로]

먼저 가장 단순한 형태로 만들어 줘.
이렇게 채워서 보냅니다모둠을 자동으로 짜 주는 도구를 만들고 싶다. 쓰는 사람은 담임교사 혼자, 교실 PC에서 쓴다. 학생 이름은 엑셀에서 붙여넣는다. 설치 없이 HTML 파일 하나로 되게 해 줘. 먼저 가장 단순한 형태로.

기능 목록은 쓰지 않습니다 — 그건 쓰면서 나옵니다.

틀 ② 기능 하나 추가할 때

복사해서 쓰기 
지금 것에서 [한 가지]를 추가해 줘.

· 왜 필요한지: [학생들이 매번 손으로 지워야 해서]
· 어디에 있으면 좋을지: [왼쪽 설정 칸 아래]
· 기존 것은 건드리지 말 것

다 되면 화면 캡처로 보여 줘.
이렇게 채워서 보냅니다남녀가 한쪽으로 몰리지 않게 섞는 기능을 넣어 줘. 모둠별로 성비가 비슷해야 활동이 잘 돌아가서 그렇다. 지금 있는 "다시 뽑기" 버튼 옆에 두면 좋겠다. 다 되면 화면 캡처로 보여 줘.

한 번에 하나만. "왜"를 붙이면 더 나은 방법을 제안받을 때가 많습니다.

틀 ③ 잘못됐을 때

복사해서 쓰기 
[내가 한 행동] 했더니 [보이는 결과]가 나온다.
기대한 건 [원하는 결과]다.

(오류 문구가 있으면 그대로 붙여넣기)
(화면 캡처가 있으면 함께)

원인을 찾아서 고쳐 줘.
이렇게 채워서 보냅니다학생 27명을 붙여넣고 4모둠으로 뽑았더니 한 모둠만 9명이 됐다. 고르게 나뉘길 기대했다. 오류 창은 안 뜬다. 원인을 찾아서 고쳐 줘.

원인 추측은 쓰지 않습니다. 행동 → 결과 → 기대, 세 줄이면 충분합니다.

틀 ④ 마무리할 때

복사해서 쓰기 
전체적으로 점검해 줘.

· 기능이 서로 망가뜨리는 데가 없는지
· 처음 쓰는 사람이 헤맬 만한 곳이 없는지
· 버전을 붙이고 설명 문서를 정리해 줘

이상 없으면 최종 파일을 줘.
이 프로젝트에서 실제로 쓴 말전체적으로 프로그램 검증하고 이제 이상 없으면 version 지정하고 정리 푸쉬하자 — 이 한 줄로 전체 점검, 버전 2.0.0 지정, 문서 정리가 한 번에 됐습니다.

07따라 하기 — 2주 일정

하루에 몰아서 하는 게 아니라 틈틈이 합니다. 실제로 손댄 날은 5일이었습니다.

때할 일메모
1일차가장 단순한 형태로 완성틀 ①로 시작 · 돌아가기만 하면 성공
2~3일차직접 써 보기 (만들지 않음)불편한 점을 메모만 해 둔다
4~5일차메모를 하나씩 요청틀 ② · 하루 2~3개면 충분
6~7일차학생 1~2명에게 시켜 보기내가 못 보던 문제가 나옴
2주차고치고 · 버리고 · 점검틀 ③·④ · 버전 붙이고 마무리
2~3일차의 "만들지 않는 기간"이 핵심입니다. 써 보지 않으면 무엇이 필요한지 모릅니다. SVG Forge도 10월 2일부터 11일까지 열흘을 쉬었고, 그 사이 쌓인 불편함이 2주차 작업 목록이 됐습니다.

08흔한 실수 다섯 가지

전부 제가 실제로 한 실수입니다. 특히 마지막은 뼈아픕니다.

01
한 번에 다 요청한다"이런 거 저런 거 다 되는 프로그램" → 어디가 틀렸는지 못 찾습니다.
02
원인을 추측해서 말한다"메모리 문제 같은데" → 엉뚱한 곳을 고치게 됩니다.
03
결과를 확인하지 않는다"됐습니다"를 믿고 넘어감 → 나중에 한꺼번에 터집니다.
04
아까워서 못 버린다이상한 기능을 붙들고 그 위에 또 쌓습니다.
05
저장을 안 한다잘 되던 시점으로 못 돌아갑니다. 한 단계 끝날 때마다 저장하거나 커밋하세요.
