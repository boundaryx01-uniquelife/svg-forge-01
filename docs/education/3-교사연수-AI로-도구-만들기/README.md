## 발표 구성

1. **무엇을 만들었나** (1~5장) — 결과물, 숫자, "필요했던 것 / 필요 없었던 것"
2. **다섯 단계** (6~16장) — 시작 · 키우기 · 고치기 · 확인 · 버리기
3. **바로 쓰는 틀** (17~22장) — 프롬프트 틀 4종, 흔한 실수
4. **직접 해보기** (23~27장) — 무엇부터, 환경, 2주 일정표

## 다섯 단계 요약

| 단계 | 핵심 | 이 저장소의 증거 |

| ① 시작 | 기능이 아니라 **쓰임새**로 말하고 제약을 먼저 못 박는다 | "MakerLab에 넣을 SVG" → RDWorks 곡선 호환 문제까지 알아서 해결 |

## 연수 진행 팁

- **11장(실제로 보낸 요청)에서 반응이 가장 좋습니다.** "지우는게 어딧지?", "만듦" 같은 실제 기록을 보여 주면 "멋진 프롬프트를 써야 한다"는 부담이 사라집니다.
- 16장(버리기)에서 실패 사례를 솔직하게 말하면 신뢰를 얻습니다.
- 18~21장(프롬프트 틀)에서 참가자가 자기 상황으로 하나 직접 써 보게 하세요. 핸드북에 복사 버튼이 있습니다.
- 24장(무엇부터)에서는 **"지금 손으로 하고 있어서 귀찮은 일"**을 떠올리게 하는 게 가장 잘 먹힙니다.

## 배포

핸드북 오프라인판은 USB나 메신저로 그냥 돌리면 됩니다. 더블클릭하면 브라우저에서 열리고, 외부 요청이 하나도 없습니다. 체크리스트 표시는 각자 브라우저에만 저장됩니다.
