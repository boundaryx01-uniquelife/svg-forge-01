### 3차: 성형 틀 (눌러 볼록하게) — 완료
원본 영상의 방식은 **주조가 아니라 열성형**이었다. 평평하게 출력한 본체(PLA)를
데워서 틀(PETG — 열에 강해서) 사이에 끼우고 눌러 돔 모양으로 바꾼다.
2차에서 만든 주조 몰드는 용도가 달라 **틀 종류 선택**으로 함께 남겼다.

- **수틀(볼록) + 암틀(오목) 한 쌍**, 같은 실루엣에서 생성 · 구면 돔
- 두 짝 사이 **간격 = 본체 두께 + 여유** (기본값은 3D 두께에서 자동)
- 플랜지로 가장자리를 잡아 주고, 네 귀퉁이 **정렬 핀**(암틀은 구멍)
- 돔이 높으면 무늬가 찢어지므로 **늘어나는 비율을 계산해 22% 넘으면 경고**
- 출력: 두 짝 / 수틀만 / 암틀만
- 패턴이 성형을 돕는다 — 통짜 판은 늘어나지 못해 찢어지지만, 뚫린 격자·거미줄은 살이 벌어지며 곡면을 따라감

#### 고친 것 (사용자 지적)
- **암틀 핀 구멍이 바닥 2.5mm 까지만 뚫려 있었다** — 위 층들에 구멍이 없어 핀이 들어가지 않음. 전 층을 관통하도록 수정
- **암틀을 뒤집어 덮으면 좌우가 바뀐다** — 비대칭 도형에서 안 맞음. 암틀을 좌우 반전해서 생성하고, 핀 하나를 굵게 만들어 한 방향으로만 맞물리게 함
- **캐비티 높이와 돔 높이의 대응이 틀렸다** — `domeH + gap - h` 로 계산해 두 면이 어긋남. `domeH - h` 로 수정 (검사 추가로 발견)
- 검사 추가: 핀 구멍 관통 여부, 뒤집었을 때 좌우가 맞는지, 캐비티가 돔보다 간격만큼 넓은지

#### 붙임 테두리 (두 장을 붙여 입체로)
완성품은 돔 한 장이 아니라 **두 장을 테두리끼리 붙인 입체**다. 붙일 평평한 면이 필요.
- **붙임 테두리 폭** 입력 — 돔은 테두리 안쪽만 올라가고 가장자리는 평평하게 남음
- 암틀은 돔 구간 위(gap 구간)에서 실루엣 전체를 비워, 평평한 테두리가 눌리지 않게 함
- 기본값은 무늬 **벽 폭을 따라감** (테두리에 무늬 구멍이 걸치면 접착이 약해지므로)
- 경고: 테두리가 벽보다 넓음 / 테두리가 너무 넓어 돔 자리가 없음

- 도형이 작아 테두리가 다 먹으면 실패시키지 않고 들어가는 만큼 줄임
- 돔 높이 기본값은 도형 크기에 맞춰 자동(늘어남 18% 이하). 직접 넣은 값은 그대로 두고 경고만

#### 성형 미리보기 탭
레이저 작업 미리보기처럼, **누르는 과정을 단면 애니메이션**으로 확인할 수 있게 함 (`src/pressview.js`).
- 5단계 — ① 본체를 수틀에 올림 ② 암틀 덮기 ③ 눌러 성형 ④ 틀 분리 ⑤ **두 장을 테두리끼리 붙이기**
- 재생·일시정지·진행 슬라이더, 단계마다 설명 한 줄
- ③ 에서 두 틀 사이 간격을, ⑤ 에서 붙는 자리를 치수로 표시
- 단면은 3D 메시를 자르지 않고 3D와 같은 층별 오프셋 계산을 2D 로만 해서 얻음 (가볍고 3D와 어긋나지 않음).
  균일 격자에 높이를 채우는 방식 — 폴리라인을 이어 붙이면 도형이 갈라질 때 윤곽이 꼬인다
- 성형 틀 종류일 때만 탭이 보임

### 2026-10-22 — 색 편집 버그 · 몰드 다듬기 · 새 작업

#### 색 바꾸기에서 구멍이 뚫리던 것
사용자 지적: *"빨간색 테두리 가장자리 얇은 네이비 선을 같은 빨간색으로 바꿨을 때 원하지 않는 영역도 같이 칠해져 버렸음"*

- 원인: 색을 옮길 때 **링(ring)만 모아서 `buildItems` 로 다시 중첩을 계산**했다.
  `buildItems` 는 중첩 깊이로 구멍/면을 판정하므로, 큰 도형 **위에 얹혀 있던** 테두리의
  바깥 윤곽이 그 도형 안쪽(깊이 1)에 들어가 **구멍으로 뒤집힌다**. 테두리 자리에 구멍이 뚫림
- 고침: `src/edit.js` 에 `unionRings(aItems, bItems)` — 양쪽의 **방향이 이미 맞는 `poly`** 를
  Clipper NonZero 로 **영역끼리 합집합**한 뒤 링으로 되돌린다. 양쪽의 구멍 의미가 모두 보존됨
- 적용 경로: `col`(색 바꾸기) · `fill`(💧 같은 색으로 / 🪣 빈 곳 채우기) · `add`(글자·도형 얹기) 세 곳 모두
- 검사 `test/colmerge.mjs` 5건 — 판 위 테두리 / 둘러싼 테두리 / 구멍 있는 판 위 테두리 / 떨어진 테두리 / fill 경로
  - 고치기 전 3건 실패 (4000mm² → 3856mm², 144mm² 구멍)

#### 구멍을 골라 색을 바꿀 때 두 색이 겹치던 것 (에이전트 검증으로 발견)
위 수정 뒤 에이전트로 이미지 10종 × 341항목을 검증해 **별개의 결함**을 찾음 (이전부터 있던 것).

- 구멍 아이템을 직접 골라 색을 바꾸면
  - 원래 색 레이어에서 그 구멍 링이 빠져 **원래 색이 구멍을 메우고**, 새 색도 같은 자리를 칠해 **두 색이 겹침**
  - 구멍 속에 떠 있던 섬은 중첩 깊이가 1 줄어 **구멍으로 뒤집힘**
  - logo.png: 검정 636.9 → 712.0(+75.1) · 겹침 82.6mm² · 섬 7.5mm² 소실
- 고침: `col` 에서 **직접 고른 구멍**(부모는 안 고른 경우)은 원래 색에 **그대로 남기고**,
  빈 곳(`emptyInside()` = 그 구멍 − 모든 색의 칠해진 면)만 새 색으로 넘김.
  `fill`(🪣)이 이미 쓰던 올바른 방식을 공통 함수로 빼서 두 경로가 같은 결과를 내게 함
- 검증 후: logo.png 검정 636.93 **유지** · 겹침 0.01mm² · 실제 이미지 UI 케이스 9건 중 구멍-col 3건 전부 통과
- `whole`(색 전체 바꾸기)에서는 구멍도 함께 옮겨야 하므로 이 처리를 하지 않음

> 참고: multi.png 에서 ink 가 0.1% 늘어 보인 것은 결함이 아님 — **아무것도 안 바꾸는 편집**만으로도
> 같은 값이 나옴. 편집 뒤 bbox 재맞춤으로 `model.width` 가 50 → 49.965 로 바뀌어 래스터 격자가
> 달라진 측정 문제. 폴리곤 면적은 644.87 → 644.85 로 보존되고 되돌리면 정확히 복구됨

#### 자유 모드에서 모드 자동 전환
- 자유 모드에서 **패턴 채우기 → 몰드 · 패턴**, **키캡 → 키캡(MX)**, **고리 → 키링/네임택** 으로 모드가 따라감
- `preset` 의 change 핸들러를 부르지 않는다 — 그 핸들러는 다른 항목을 전부 프리셋 기본값으로 되돌리므로,
  사용자가 켜 둔 받침판·너비가 날아간다. 모드 표시(`autoMode()`)만 바꾸고 안내 문구를 띄움
- 체크를 **끌 때**는 모드를 바꾸지 않음(제멋대로 자유로 돌아가면 혼란). 무늬 종류·색만 바꿔도 안 바뀜
- 이미 어떤 모드에 있으면 건드리지 않음. 다른 모드에서는 이 체크박스들이 숨겨져 있어 눌릴 일도 없음

#### 틀에서 솟은 부분 없애기 · 매끈한 돔
사용자 지적: *"몰드의 틀에 기둥이나 송곳처럼 돌출되는 부위는 없애자"*

- **정렬 핀 네 기둥 제거**. 대신 **판의 한 귀퉁이를 비스듬히 잘라** 방향을 표시한다
  (`info.key`). 암틀은 좌우 반전해 만들므로, 뒤집어 덮었을 때 잘린 귀퉁이끼리 맞으면 방향이 맞다.
  솟는 부분이 없어 출력 받침이 필요 없고, 핀 구멍 관통 문제도 사라졌다
- **틀 면은 매끈한 돔만** — `smoothSil()`: 바깥 윤곽만 남기고(눈·입 구멍 메움) **열림 연산**
  (안으로 r → 다시 밖으로 r, r = 짧은 변의 3%, 0.6~1.5mm)으로 가는 돌기를 없앤다.
  열성형에서 이런 뾰족한 자리가 본체를 찢는 원인이었다. `smooth: false` 로 예전 동작
- 성형 미리보기(`pressProfile`)도 같은 실루엣을 쓰게 해 3D와 어긋나지 않게 함
- UI: 「정렬 핀」 칸 삭제 → 「낼 짝」으로 바꿈
- 검사 `test/press_check.mjs` — 플랜지 위 솟은 점 0개 / 잘린 귀퉁이가 두 짝에서 반대쪽 /
  눈 구멍 2개 → 0개 / 송곳 있는 도형 세로 84mm → 60.2mm / 메시 닫힘

#### 무늬 사이 구멍을 두 번째 색으로 채우기
사용자 지적: *"2색 이상으로, 생기는 구멍들은 다른 색으로 채워진다고 생각하고 만들자"*

- 「구멍을 다른 색으로 채우기」 (기본 켬) + 「채움 색」 — 무늬 사이 빈 곳을 **같은 두께로** 채워
  뚫린 곳 없는 2색 판이 된다. 3MF 에서 색이 나뉘어 나옴
- 도형 자체의 구멍(눈·입)은 실루엣에 없으므로 **그대로 비어 있다**
- 무늬가 촘촘한 곳의 채움 조각은 노즐보다 가늘어 출력이 안 되므로,
  **0.8mm 미만 조각은 무늬 색으로 합쳐** 넘긴다 (유령·거미줄 기준 가는 부분 31곳 → 16곳)

#### 실루엣 버그 둘 — 채운 구멍이 깨짐 · 색 수를 늘리면 눈이 사라짐
사용자 지적: *"눈을 채움으로 채우면 단순히 면이 채워지는 게 아니라 이상하게 변함"* ·
*"색 수를 늘리면 눈이 없어져 버림"*

둘 다 `applyPattern` 의 **실루엣 만드는 법**이 원인이었다.

1. **레이어를 한꺼번에 EvenOdd 로 합쳤다** — 색끼리 겹치는 자리가 서로 지워진다.
   채우기로 구멍을 메우면 그 원반이 원래 구멍 테두리와 겹쳐 실루엣이 누더기가 되고,
   무늬가 그 자리를 비켜 갔다. → 레이어마다 EvenOdd 로 먼저 모으고 **NonZero 로 합침**
2. **경계에 남는 미세 구멍** — 채운 원반과 원래 구멍 테두리가 µm 단위로 어긋나 실오라기 구멍이 남는데,
   `offset(sil, -wall)` 이 그 둘레를 깎아 내 **벽 폭만 한 덩어리**가 박혔다 (사용자가 본 "이상한" 것).
   → 실루엣에 `clean(sil, 0.05)` 로 찌꺼기 제거
3. **색 수를 늘리면 눈이 사라짐** — 「안쪽 같은 색 면은 남김」이 켜져 있으면 유령의 흰 눈이
   *흰 면*으로 잡힌다. 실루엣이 모든 레이어의 합집합이라 눈이 메워졌다.
   → 트레이싱이 **배경색**(`layers.bgColor`, 모서리 색)을 같이 넘기게 하고,
   실루엣에서 **그 색 레이어를 빼서** 안쪽 같은 색 면은 뚫린 자리로 본다
   (`imagetrace.js` → `worker.js` → `app.js: S.bgColor` → `applyPattern`)
- 검사 `test/patfill.mjs` — 원 안을 격자로 찍어 색별 덮인 비율로 본다.
  구멍은 1% / 채운 눈은 100%(무늬 46% = 몸통과 같음) / 찌꺼기 덩어리 0개 /
  배경색을 알려 주면 흰 눈이 1%, 모르면 100%(예전 동작) / 3색 겹침에서 빈 곳 없음

#### 칠한 색이 무늬에 먹히던 것
사용자 지적: *"눈을 빨간색으로 채우니 눈이 사라지고 이상한 점이 생김"*

앞의 수정으로 실루엣은 멀쩡해졌지만, 칠한 빨강이 **실루엣에 통째로 흡수돼** 그 위로 무늬가 깔렸다.
눈을 빨갛게 칠했으면 **빨간 눈**이 나와야 한다.

- `applyPattern` 이 레이어를 넓이 순으로 보고, **가장 넓은 색만 '바탕'**(무늬를 까는 곳)으로 쓴다.
  나머지 색 면은 **제 색 레이어로 그대로 남기고**, 그 자리에는 무늬도 채움색도 올리지 않는다
  (색이 겹치면 3D에서 같은 자리에 두 번 쌓인다)
- 단, 노즐보다 가는 색 면(`offset(-0.4mm)` 하면 사라지는 것)은 제 색으로 뽑을 수 없으므로 바탕에 합친다.
  트레이싱 가장자리에 생기는 실오라기 색(안티에일리어싱)이 여기 걸린다 — 3색에서 `#858585` 가 그 예
- 검사 `test/patfill.mjs` 에 추가 — 빨강 눈 99% 보존 / 그 위 무늬 1% / 채움색 0% /
  빨강이 제 레이어로 남음 / 0.4mm 색 띠는 바탕에 합쳐짐

#### 칠한 색의 테두리 · 무늬를 켠 채로 칠하기
사용자 지적: *"채움을 하면 눈에 있던 테두리가 사라짐"* · *"한번 채우고 나면 다시 칠할 수 없게 잠겨버림"*

- **테두리**: 구멍일 때는 그 둘레에 벽(`실루엣 − 안쪽`)이 생기는데, 칠해서 면이 되면
  둘레가 실루엣 경계가 아니게 되어 벽이 사라졌다. → **칠해 둔 색 면 둘레에도 같은 폭으로 벽**을 두름
  (`offset(kept, wall) − kept`, 실루엣 안쪽만)
- **"잠김"**: 무늬를 켜면 🪣 채우기 줄이 숨겨져서, 칠하려면 무늬를 껐다 켜야 했다.
  → 무늬를 켠 채로도 채우기가 되게 함. 집는 대상은 **무늬를 씌우기 전 도형**(`S.silModel`) —
  화면은 무늬지만 누른 자리의 원래 면을 칠한다. 도형 편집 도구(선택·삭제·두께)는 그대로 숨김
  (편집 대상이 달라 혼란)
- `updateEditBar()` 가 `checkSel()` 단계에서 먼저 돌아 `S.silModel` 이 아직 없을 때 판정되던 것도 고침
- 검사: `patfill.mjs` 에 "칠한 색 둘레가 무늬 색으로 100% 덮임" 추가,
  `mold_ui.py` 에 "무늬를 켠 채로 채우기 줄이 보임" 추가

### 2026-10-23 — 미해결 버그 원인 규명 (에이전트 3팀)

에이전트 셋을 각각 **자유 모드 칠하기 / 몰드·패턴 칠하기 / 색 더하기·빼기** 로 나눠 돌려
총 **1100건 넘는 수치 검사**를 했다. 어제 "재현이 안 된다"던 버그의 **원인을 찾아 고쳤다.**

#### 왜 어제는 재현이 안 됐나
기존 검사(`patfill.mjs`·`mold_ui.py`)와 샘플 유령은 전부 **색 레이어 1개·도형 1덩어리**였다.
아래 두 버그는 **색 면이 2개 이상일 때만** 나타난다.

#### 고친 것 ① 바탕이 매번 다시 뽑혀 무늬가 통째로 옮겨 다님 《치명적》
`applyPattern` 이 **넓이 순으로 매 렌더마다 '바탕'(무늬가 깔리는 색)을 다시 뽑고** 있었다.
칠하다가 넓이 순위가 뒤집히는 순간 바탕과 '칠한 색'이 서로 자리를 바꾼다 →
- 칠한 색이 바탕이 되어 **무늬에 먹혀 사라지고** (파랑 317.6mm² → 레이어 없음)
- 원래 몸통이 '칠한 색' 취급을 받아 **무늬도 구멍도 없는 통짜 면**이 되고
- 앞서 칠한 구멍의 **테두리가 44% → 0%** 로 사라진다

→ **트레이싱 시점의 바탕색을 고정**해서 쓴다. `app.js` 가 편집하기 **전** 모델에서 가장 넓은 색을
재어 `S.moldBase` 에 두고 `applyPattern(o.baseColor)` 로 넘긴다. 그 색을 통째로 칠해 없앴으면
가장 넓은 색으로 떨어진다. 사용자가 말한 **"채우면 테두리가 사라짐 · 다른 부분 채우면 또 사라짐"** 이 이것.

#### 고친 것 ② 색 면 안에 든 색 면에는 테두리가 아예 안 생김 《높음》
벽을 **칠한 색 전체의 합집합 바깥**에만 둘렀다. A 색 면 안에 B 색 면이 들어 있으면
B 는 합집합 안쪽이라 띠가 생기지 않는다(multi.png·touching.png 에서 2.5mm 밖까지 무늬색 0%).
→ **색마다 제 면 바로 바깥에 따로** 두르고, 다른 색의 테두리가 지나가는 자리는 그 색 면에서 덜어낸다.
0.3~1.8mm 전 구간 무늬색 100% 확인.

#### 고친 것 ③ 색을 고른 뒤 🪣 를 누르면 꺼져 '잠김' 《중간·재현 100%》
색 칸을 건드리면 채우기가 켜지는데, 그 다음 🪣 버튼을 누르면 **토글이라 꺼져 버린다.**
🪣 툴팁이 *"색을 고르고 켠 뒤"* 라고 안내하므로 **안내대로 하면 반드시 잠겼다.**
→ 색으로 켜진 직후의 🪣 누름은 '켜려는 것'으로 보고 켠 채 둔다. 한 번 더 누르면 평범하게 꺼진다.
사용자가 말한 **"한 번 채우고 나면 다시 채울 수 없게 잠겨버림"** 이 이것.

### 2026-10-25 — DXF 단위·색 번호 (레이저에서 재료가 날아가던 둘)

출력 실무 에이전트가 찾은 2번. `src/export.js` 한 파일.

**단위가 없었다.** 헤더 변수가 `$ACADVER` 하나뿐이라 RDWorks·LightBurn 이 제 설정대로 가정한다.
인치로 잡히면 80mm 짜리가 2,032mm 로, 반대면 3.15mm 로 들어온다. 버튼 툴팁에는 "단위 mm" 라고
쓰여 있지만 파일에는 그 정보가 없었다.
→ `$INSUNITS=4`(mm) · `$MEASUREMENT=1`(미터법) · `$LUNITS=2` · `$EXTMIN`/`$EXTMAX` 추가.
`$ACADVER` 는 AC1009 그대로 뒀다 — 버전을 올리면 엔티티 구조까지 바꿔야 하고,
두 프로그램 모두 버전과 상관없이 이 변수들을 읽는다.

**색 번호가 9개뿐이라 뭉쳤다.** `nearestAci()` 가 ACI 9색 중 가까운 것만 골라,
`#ff0000`(절단)·`#ff3333`(새김)·`#cc2222`(절단) 이 전부 ACI 1 이 됐다.
무채색 팔레트는 전부 8. RDWorks 는 DXF **색**으로 작업을 가르므로
**새김으로 지정한 자리가 절단으로 타서 작품이 두 동강 난다.**
→ 가까운 색을 먼저 쓰되, 이미 쓴 번호면 1~255 중 빈 번호로 민다.
색 자체는 원래와 달라질 수 있지만 레이어 이름에 hex 가 들어 있어 어느 색인지 알 수 있다.
(전체 256색 팔레트를 넣으면 화면 색까지 맞출 수 있는데, 정확성과는 무관해 미뤘다.)

  - **스템 뿌리**: 천장 쪽이 가장 굵고(Ø5.5 + 2×R) 멀어질수록 Ø5.5 로 가늘어지는 1/4 원 필렛.
    별도 파트 `스템 뿌리` 로 나간다. 스템이 뿌러지는 걸 막는다
  - **안쪽 벽 → 천장**: `bodyMesh` 의 안쪽 벽을 천장 앞에서 1/4 원으로 말아 들여 오목한 모서리를 없앰
  - 키캡은 **윗면을 바닥에 놓고 뒤집어** 출력하므로, 천장이 바닥 쪽·필렛이 위로 갈수록 가늘어진다
    → 층마다 재료가 줄기만 해서 **서포트가 필요 없다**. 메시에서 반지름을 재어 단조 감소를 검사
  - 상한: 천장 두께(`zi - 0.6`)와 벽 폭(`wall × 1.5`), 최대 2.5mm
- 검사 `test/kc_round.mjs` — R 을 키우면 실제로 깎이는지(부피), 전 구간 **열린 모서리 0**,
  얇은 글자가 사라지지 않는지, 상한 clamp, 기본값, 스템 뿌리 반지름 프로파일이
  천장 쪽에서 가장 굵은지(2.77 → 3.25mm)

### 이미지 도형 편집 (2D 미리보기)
- **선택**: 클릭 / **Ctrl·Shift+클릭** 여러 개 / 빈 곳을 끌어 **영역 선택**
- **편집**: 삭제(Delete), 구멍 채우기, 두께 −/+ (같은 편집에 누적 → 늘렸다 줄이면 원상복구), 색 바꾸기·합치기, 끌어서 이동, 범위(이 도형만 / 이 색 전체)
- **✂ 끊기**: 선을 그어 연결된 부분을 틈(폭 mm)으로 분리, 지워질 띠 미리 표시
- **💧 같은 색으로**: 선택한 도형을 눌러 둔 이웃 면의 색 그대로 묶기 (이웃 색은 안 바뀜)
- **🪣 채우기 (페인트 통)**: 색을 고르고 칠할 면 클릭 — 도형은 색 변경, 빈 구멍은 그 빈 곳만 새 색으로 채움, 텍스트 모드에서는 글자 색. Alt+클릭은 색 집기. 마우스를 올리면 칠해질 면을 반투명으로 미리 보여 주고, 칠할 게 없으면 🚫 커서
- **T 글자 넣기**: 글자·크기·색·**최소 획 폭(3D 출력용, 기본 0.8mm)** 지정 → 클릭한 자리에 배치. 지금 획 폭(보통·가장 가는 곳) 미리 표시
- **✎ 글자 고치기**: 넣은 글자를 선택하면 내용·크기·획 폭·색·자리 변경, 지우기
- 편집은 '편집 목록'으로 저장 → 실행 취소·프로젝트 저장·너비 변경과 호환 (너비를 바꾸면 모든 편집이 같은 비율로 따라감)
- 옮기거나 키운 도형·글자가 다른 색 위에 놓이면 아래 색을 도려내 3D 겹침 방지
- 화면 이동: 휠(가운데) 버튼 끌기 또는 Space+끌기

### 3D 출력용 가는 부분 확인 (2D)
- 레이저 외 모드에서 **0.8mm 미만 부분·아주 작은 조각을 2D에 빨간색 표시** (⚠ 가는 부분 버튼으로 켜고 끄기)
- 경고 옆 **가는 부분 보정 (0.8mm)**: 가는 조각만 모자란 만큼 키우고 이웃 색에서 도려냄 → 2D에서 결과 확인·되돌리기 가능

- 획 폭은 글자를 그림으로 그려 거리 변환으로 측정 (시험 막대 기준 오차 ≈0.01mm)
